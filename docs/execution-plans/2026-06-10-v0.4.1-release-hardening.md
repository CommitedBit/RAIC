# Execution Plan: post-v0.7.0 Release Hardening

Date: 2026-06-10
Target release: post-`v0.7.0` hardening slice
Milestone name: Release Hardening

## Summary

This is a conservative hardening track to stabilize the already-live behavior from `v0.7.0`. It adds diagnostics and release clarity without changing public payloads, classroom user flows, or API contracts.

## Milestone 0: Baseline

- `v0.7.0` is live on `main` and is the behavioral baseline.
- This hardening track should remain one-purpose and reversible in every slice.
- Teacher-facing and student-facing runtime behavior must stay unchanged until explicit follow-up gates pass.

## Milestone 1: Governance Observability

Scope:

- Add provider-governance telemetry for:
  - scenario denials,
  - managed fallback routing,
  - and legacy unmanaged-path usage.
- Keep existing route responses and permission checks unchanged.

Acceptance:

- A single run that triggers scenario governance edge cases produces explicit telemetry for denial, fallback, and legacy usage classification.
- No public/student request or response schema changes are introduced.
- Existing behavior remains unchanged for stable classroom generation and presentation routes.

## Milestone 2: Request/Audit Visibility

Scope:

- Expand failure observability around provider and generation errors.
- Tighten smoke-gate context and audit visibility for request failures and fallback decisions.
- Ensure debug/recovery signals support release triage without changing external contracts.

Acceptance:

- Failure and fallback pathways can be reconstructed from internal telemetry and logs.
- Smoke-test outputs include the same context needed to classify request-path regressions.
- No user-visible contract changes are introduced.

## Milestone 3: Release Documentation

Scope:

- Update release guidance where links, assumptions, or stale commands remain.
- Keep all docs in sync with Node 24 and execution-plan references.

Acceptance:

- Route links and commands in the active milestone docs are validated and current.

## Rollout and Gates

Run local release gates under Node `24.x` from a clean local `main` checkout. Scratch branches can
run targeted checks, but `secrets:scan`, `ops:drift`, and `ops:verify` intentionally enforce the
single-branch handoff policy.

Before merge:

- `corepack pnpm run secrets:scan`
- `corepack pnpm run ops:drift`
- `corepack pnpm run lint`
- `corepack pnpm run build`
- `corepack pnpm run check`
- `corepack pnpm run test:mirofish:gate`
- `corepack pnpm run test:mirofish:e2e`
- `CI=1 corepack pnpm run test:e2e`
- `corepack pnpm run benchmark:milestone`
- `corepack pnpm run ops:verify`

If this hardening track touches latency-sensitive generation/provider paths:

- Run `corepack pnpm run benchmark:milestone`, attach the non-fixture benchmark artifact, and
  compare to `data/perf-results/latest.json` before `corepack pnpm run ops:verify`.

Post-deploy verification:

- `corepack pnpm run smoke:production:milestone`

## Rollback Conditions

- Remove scope if diagnostics reveal unstable classroom behavior for stable flows.
- Roll back if any diagnostic changes affect runtime outcomes outside managed observability and reporting.
- Keep changes in isolated, reviewable commits for clean revertability.
