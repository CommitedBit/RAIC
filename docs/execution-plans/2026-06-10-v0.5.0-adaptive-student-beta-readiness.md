# Execution Plan: post-v0.7.0 Adaptive Student Beta Follow-up

Date: 2026-06-10
Target release: post-`v0.7.0` adaptive-student follow-up slice
Milestone name: Adaptive Student Beta Follow-up

## Summary

Student-facing adaptation should expand only after a dedicated privacy/compliance and safety bundle is complete. Until those gates pass, public/student behavior remains unchanged.

## Milestone 1: Privacy and Compliance Readiness

Scope:

- Add explicit consent/consent-default behavior for student adaptation features.
- Add retention and retention-verification for adaptation artifacts.
- Clarify data-sharing boundaries and leakage control expectations.

Acceptance:

- Consent and retention design is documented and implemented consistently for student adaptation paths.
- Tests verify retention rules for adaptation artifacts and negative cases when retention policies are incomplete.
- No student-facing behavior is changed before this slice is complete.

Implementation tasks:

- Define consent defaults as disabled until an explicit student-adaptation consent signal exists.
- Define adaptation artifacts as derived records with retention ownership, deletion expectations, and verification coverage before persistence is added.
- Add retention-verification tests that fail when adaptation artifacts are missing a retention policy or cleanup proof.
- Document data-sharing boundaries between teacher/internal analytics and student/classroom-cookie routes before enabling any student entrypoint.

## Milestone 2: Student Adaptation Controls

Scope:

- Add student-adaptation entrypoints behind feature flags.
- Gate entrypoints by teacher policy and existing role checks.
- Keep behavior fully rollback-safe via feature-flag disable and policy flips.

Acceptance:

- Student adaptation defaults to disabled.
- Teacher policy and flags can fully prevent student adaptation without code changes.
- Disabling flags restores baseline student behavior observed in the current `v0.7.0` production line.

Implementation tasks:

- Keep `RAIC_STUDENT_ADAPTATION_BETA` default-off and server-only.
- Gate any future student adaptation loader through teacher policy plus explicit consent.
- Treat a disabled flag as the highest-priority rollback decision, even when policy and consent are enabled.
- Do not wire student-facing adaptation into chat, PBL, or generation routes until privacy and leakage tests are green.

## Milestone 3: Deterministic Replay and Isolation

Scope:

- Add deterministic replay/observability tests for mixed teacher/student flows.
- Prove no student payload leakage into teacher/private analytics channels.
- Confirm that student-side adaptation artifacts do not alter public/student API shapes.

Acceptance:

- Replay tests cover mixed-path interaction and rollback scenarios.
- No unreviewed student payload changes are present in teacher/internal artifacts.
- Public/student API contract remains unchanged.

Implementation tasks:

- Add mixed teacher/student replay tests that prove teacher adaptive context is not loaded for classroom-cookie students.
- Add leakage tests with student-only sentinel values and assert teacher/internal analytics remain scoped.
- Add student-visible payload contract tests that reject adaptive/private markers in classroom responses.
- Add rollback tests that compare flag-off and explicit-false behavior before any student adaptation loader can run.

## Slice Exit Criteria

- Privacy and retention tests must pass, including leakage and rollback tests.
- Student path remains disabled by default until all slice acceptances pass.
- Student-facing adaptation is feature-flagged, teacher-policy guarded, and fully rollback-safe.

## Rollback Conditions

- Roll back immediately if student artifacts leak into public/student API behavior or introduce retention inconsistencies.
- Roll back if teachers can observe or control adaptation outside approved policy pathways.
- Preserve a single-slice revert path for each feature-flag-gated feature.
