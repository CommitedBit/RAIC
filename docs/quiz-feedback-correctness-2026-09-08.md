# Quiz answer keys and feedback

Generated and imported choice questions could store a label such as `(6, 2)` or a padded value such as ` A ` as their answer key, while the learner selected `A`. Exact comparison then marked the correct response incorrect. A missing choice key could also enter short-answer AI grading, and failed AI grading awarded invented half-credit.

The shared quiz normalizer now resolves trimmed identifiers and exact labels only when they identify one option. It supports scalar and array keys, the existing `answer`, `correctAnswer` and `correct_answer` fields, string options, multiple selections, and the legacy `text` alias for `short_answer`. Conflicting aliases, unknown or ambiguous answers, repeated option identifiers and invalid single-answer counts remain invalid. It does not split punctuation, alter mathematical notation, case-fold identifiers or guess from fuzzy text. Successful normalization keeps one canonical answer field; invalid keys retain their source values for teacher correction.

Generation rejects malformed quizzes before they become lesson content. The same normalization applies to server classroom writes, updates and legacy reads, and browser save, read, backup import and export paths. It does not mutate the source object or rewrite legacy records merely because they were read.

Choice questions with invalid keys show a teacher-review message, cannot block submission of the remaining questions, and are excluded from earned and possible scores. They do not enter short-answer AI grading. Their report is neutral, with no wrong-answer styling or unsupported answer explanation. Completion summaries also exclude them. When every question is ungraded, the report shows a neutral message rather than an invented percentage.

Saved choice grades are recalculated from the current normalized questions and saved selections, including on reload. Valid saved short-answer feedback is retained without another provider request. Failed or malformed short-answer grading responses leave the answer saved and ungraded, with no fabricated credit. Legacy fallback results with unknown correctness are handled the same way.

Verification covers the five original failures and the canonical-ID control, exact math labels, conflicting aliases, option ambiguity, multiple-answer sets, idempotent normalization, real JSON storage and mocked Postgres/Dexie boundaries. Browser tests exercise actual IndexedDB, answer submission, corrected legacy results, neutral feedback, provider failure and reload. The browser provider responses are synthetic; they do not establish production or paid-provider grading accuracy. Exact commit and terminal gate evidence are recorded in the implementation report. This slice keeps version 0.9.2 and does not change provider enablement, consent, retention or deployment state.
